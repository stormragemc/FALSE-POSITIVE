# AI security

This document records AI-security tasks only after they have been implemented.

## S1: Filter AI output before it is spoken

### What is being protected and why

The detective's reply is generated by Gemini and then spoken aloud through text-to-speech. The
reply is therefore an untrusted value at the point it leaves Gemini, even though the prompt tells
the model to stay in character.

We need to stop the detective from telling a player that it knows they are lying, treating vocal
affect as proof, exposing internal prompts or labels, or producing an excessively long reply. This
protects the player experience and keeps the game honest about what its AI can actually do.

### How we are going to do that

The reply path is:

```text
Gemini response -> llm._spoken_text() -> output_safety.filter_spoken_text()
-> llm.generate_reply() -> tts.synthesize()
```

`Sidecar/llm.py` calls `filter_spoken_text()` immediately after it extracts non-thought text from
the Gemini response. The filter is pure and has no network calls or session state. It first
collapses whitespace, then returns the trusted fallback line when the text is empty, longer than
`MAX_SPOKEN_CHARACTERS` (480), or matches a blocked regular expression:

> Let's come back to that.

The blocked patterns cover:

- direct claims that the player or witness is lying, truthful, or deceptive;
- claims that a player's voice, tone, speech, pauses, or affect proves or confirms something;
- diagnostic terms such as a lie, truthfulness, affect, or emotion score, probability, detector,
  model, analysis, reading, or label;
- internal markers such as `system prompt`, `COP_PERSONA`, `LOCAL_AFFECT_CONTEXT`, and
  `WITNESS_TRANSCRIPT`.

The filter does not edit an unsafe reply. It replaces the full reply with the fallback, so a
partially unsafe sentence cannot reach `tts.synthesize()`. It deliberately does not block normal
interrogation language such as "You are a suspect," because the rule is about claims made from the
model or vocal analysis, not every discussion of the case.

### How we are going to test that the safety filter works

Unit tests in `Sidecar/tests/test_output_safety.py` import the filter directly, so they do not need
API keys, network access, Gemini, or text-to-speech. They check that:

- an ordinary detective question is allowed;
- whitespace is normalized;
- direct lie claims are replaced with the fallback;
- voice-as-proof claims are replaced with the fallback;
- leaked scores and internal context markers are replaced with the fallback;
- empty and overlong replies are replaced with the fallback.

`Sidecar/tests/test_llm_prompt_boundary.py` adds the integration boundary. It mocks a Gemini reply
containing "You are lying." and verifies that `llm.generate_reply()` returns the fallback rather
than the model text. This proves the filter sits in the reply path before the sidecar calls
text-to-speech.
